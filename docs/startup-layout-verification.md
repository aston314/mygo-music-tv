# 启动页布局修复 — 2026-11-12

SHIELD 的 v0.1.3 冷启动录屏复现：图标和状态行居中，版本号却位于屏幕左侧。原生垂直 LinearLayout 为没有显式 LayoutParams 的版本 TextView 分配整行宽度，而文本默认左对齐。系统 ProgressBar 的实际圆环还包含设备相关的 drawable 内边距，让圆环贴近音符。

修复：

- 版本行显式使用 WRAP_CONTENT，并居中文本，与其它两行共享父容器的中心轴。
- StartupLogoView 在控件外缘绘制圆环，音符占控件直径的 46%，不再依赖系统 ProgressBar 的内边距。圆环自身旋转，音符保持居中；核心启动失败后停止绘制加载环。
- 原生失败重试按钮使用内容宽度和独立顶部间距，避免默认铺满屏幕。
- Web 启动页音符从 66px 缩为 58px，独立容器消除 SVG 基线偏移；版本行预留 24px 高度，在配置返回前后保持整体位置稳定。

验证：

1. 在 192.168.2.117 的 Android 11 / WebView 120 环境录制旧版冷启动，确认上述错位。
2. 将源码中的 showStartup 方法及修复后的 StartupLogoView 编译为临时绘制探针，在同一台 SHIELD 上调用 Android 原生 measure/layout/Canvas。探针只读取已安装应用的图标与字符串资源，未替换正式 APK，也未读取账号或会话。
3. 原生绘制覆盖 960×540、1920×1080 和深浅主题共四组：Logo、状态行、版本行均在窗口中线 ±1px 内，三行不重叠；圆环到图标包围框角点的最小空隙约 27px（density 320）。
4. Playwright 覆盖桌面与 Android 类移动视口、深浅主题及 960×540、1280×720、1920×1080、928×696，检查三行居中、圆环空隙和配置返回前后位置稳定，两个测试通过。

本轮不创建新版本标签；117 已安装的正式版本仍为 v0.1.3。原生绘制验证不等于新版 APK 的冷启动验收。证据保存在忽略目录 build/tv-qa/startup-layout/，包括旧版冷启动录屏和新布局的原生绘制图片。

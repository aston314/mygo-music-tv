# 插件检查、更新与国内下载线路

真实模式启动后后台检查已安装的 GitHub 插件，每个插件每 24 小时检查一次。插件市场提供“检查全部更新”，详情提供单独检查；后台只查询版本元数据，不自动下载或安装。预览源不访问 GitHub。

市场卡片展示安装状态、当前版本和“有更新”徽标。详情展示当前版本 → 目标版本，点击“更新到 …”才下载安装。版本检查失败保留上次发现的更新，安装失败可重试；重启保留检查时间、目标版本和对应下载地址。版本未变不重复下载。

## 国内下载回退

公开插件的版本 API 与 ZIP 下载共用以下顺序：

1. `https://gh-proxy.com/` + 原 GitHub URL
2. `https://v4.gh-proxy.org/` + 原 GitHub URL
3. `https://gh-proxy.org/` + 原 GitHub URL
4. 原 GitHub URL 直连

查询和下载分别记录线路健康状态，失败线路冷却 5 分钟；不存在的 Release 不计为线路故障。单次 API 请求最多 10 秒；单个插件完整检查最多 45 秒，最多同时检查 3 个插件。下载等待响应最多 8 秒，连续 15 秒无数据换线，持续有数据的单次下载最多 3 分钟。

HTTP 错误、网页验证码、结构错误的版本 JSON、传输中断、不完整 ZIP 和 CRC 错误都触发回退。ZIP 大小、文件数、解压大小、路径、插件 ID、JS 编译和运行时兼容性仍按安装器的限制检查。CRC 用于检测损坏，不替代作者签名。切换线路始终使用已选定版本的地址，不重新选择 latest。

代理仅用于公开插件安装器的 GitHub 请求。音乐服务账号、插件运行时 fetch、播放流与官方目录页面保持自己的网络路径；携带 GitHub 凭证的请求仅直连，不转发到公共代理。应用也不借用开发者 GitHub CLI 凭证。线路故障时显示通用的备用线路提示，地址仅作为诊断信息。

2026-11-11 从开发网络验证三条线路的 GitHub Release 元数据、Raw 插件配置与小型源码 ZIP 返回有效内容；这不代表中国大陆各运营商或电视实机的连通性。

同日使用真实预览的独立数据副本检查 9 个已安装插件，全部完成检查，并通过市场详情将 `qile222/mygo-music-qishui` 从 `0.8.1` 更新至 `0.8.2`。更新后插件数据目录逐文件哈希与原副本一致，详情显示“已是最新版本”；原来的播放预览会话保持运行。

## 安装与播放状态

更新沿用同一仓库实例的数据目录，账号、设置和插件存储保持原位；代码替换、加载与实例元数据写入验证成功后才退役旧实例，验证失败恢复旧代码。不同仓库的数据继续隔离。

更新完成不切换浏览中的音乐源，不重建队列或媒体。普通 HTTP 音频已解析后可继续播放；该源正准备播放或控制远端设备时阻止激活并提供重试，避免退役播放器仍依赖的实例。

新版本新增网络域名或外部程序声明时，下载后暂停，列出新增声明供用户确认。取消、返回或确认前已关闭详情会丢弃该下载并保留旧版。即使确认，电视端仍禁止执行外部程序。

## HTTP 接口

- `GET /api/plugins/updates`：获取已安装插件的检查及更新状态。
- `POST /api/plugins/check-updates`：`{}` 检查全部，`{instanceId}` 检查单个；异步返回。
- `POST /api/plugins/update`：`{instanceId, version}` 安装缓存中对应的确切目标版本。
- `GET /api/jobs/{id}`：查询下载、安装、失败或等待确认状态。
- `POST /api/jobs/{id}/confirm`：`{allow:true|false}` 确认或取消已下载版本的新增权限。

接口沿用本机会话认证、Origin 校验及请求大小限制。市场轮询原位更新状态；异步结果不重建卡片，不改变焦点、阅读位置或当前页面。

# 卡片文字与海报焦点

## 显示规则

- 海报卡片、插件卡片及推荐大卡的标题完整换行，不限制行数，也不添加省略号。
- 卡片副标题保留单行，超出宽度时显示省略号。
- 歌单卡片只显示名称与插件提供的 `trackCount`，例如 `43 首`；不显示创建者或描述。缺失、负数、非整数等无效数量不显示。明确提供的 `0` 显示为 `0 首`。
- 没有有效副标题时不渲染空文字行，也不再使用“打开聆听”占位。
- 海报卡片仍然只有一个可操作焦点，点击文字也能打开详情。视觉焦点只围绕海报：4px 外框与图片之间留出 3px 空隙，与淡色主题红色按钮的焦点间隙和粗细统一，保留图片圆角；不框住文字，不缩放卡片。
- 插件卡片没有海报，沿用整张卡片的焦点。
- 同一行的海报顶端对齐，卡片高度随各自标题变化，避免横向移动时焦点随图片上下跳动。焦点框预先生成，移动时只切换可见度，不反复创建和删除布局对象。

1920×1080 的 Chromium 浏览器、4 倍 CPU 降速、相同的一份真实首页数据和已解码图片，连续执行 64 次方向键：

| 同一轮对比 | 修改前的外框 | 预先生成外框后 |
| --- | ---: | ---: |
| `Layout` 事件数（包含初始对焦） | 67 | 3 |
| 按键分发中位耗时 | 1.44 ms | 0.90 ms |
| 按键分发 P95 | 2.98 ms | 2.29 ms |

外框预生成与对齐调整后，海报、遥控焦点、鼠标及滚动相关 28 项回归检查通过。

对齐前真实推荐歌单同排海报出现约 23–46 屏幕像素的高度差；顶端对齐后各排差值均为 0。方向键选择算法保持不变。以上是一次开发机对比，不能据此宣称电视端帧率或流畅度已得到实机验证。跟踪文件保存在忽略目录 `build/card-focus-*-trace.json`，并增加了同排海报对齐的浏览器回归断言。
